# 规则分工与兼容性检查

## 谁负责什么

| 范围 | 负责来源 | 本工具的处理 |
| --- | --- | --- |
| 安全、指令层级、工具权限 | 宿主与适用任务约束 | 不修改，不因风格指令扩大权限 |
| 本轮文体、语言、精确格式、编辑范围 | 用户本轮明确要求 | 优先于本工具默认偏好 |
| 投稿格式、章节流程、术语、双语关系 | 当前项目及已采用的 TJU/Nature 等框架 | 沿用，不重复运行 |
| 清晰表达、删重复、局部编辑 | `rules/expression.md` | 默认执行 |
| 学术主张、章节分工、比较与归因 | `rules/academic-writing.md` | 仅实际学术写作任务读取，补充同一次核对 |
| 表达开关与提示 | 现有 session/client 状态 | 通用与论文规则共用，不新建开关 |

不把不同层次写成一条可以覆盖一切的优先级。用户指定文体不能改变事实标准；项目要求双语时，暂停表达规范不等于取消双语任务。互不相容且影响当前产物的具体要求才需要澄清。

## 场景验收清单

下表是人工检查规则与输出时的预期，不是模型质量测试结果。自动测试只能证明所列程序行为，不能证明模型始终正确遵守。

| 输入/项目条件 | 预期行为 |
| --- | --- |
| 普通技术问答，文本里提到“摘要” | 不自动展开章节规划，不注入论文规则全文 |
| 用户要求只输出 JSON | 不在正文添加状态标记或额外修改说明 |
| 用户要求保留个人文章的第一人称和幽默 | 保留文体，不自动改成学术腔 |
| 用户只让润色摘要，有全文上下文 | 全文用于核对，只改授权范围；不默默换立论 |
| 项目已有 TJU 摘要入口 | 沿用其流程，将附加规则用于同一次检查，不再调用一轮写作技能 |
| 项目已采用 Nature 格式 | 不以通用规则更改其章节或引用格式 |
| 主张“多数数据集改善” | 保留范围，不升级成“所有数据集显著改善” |
| 旧规则要求“打不赢的指标不设为比赛” | 研究问题决定评价目标；调整协议须说明，不根据胜负隐藏相关结果 |
| 项目要求英文主稿、中文译稿 | 同步最终语义和限定，不为中文满行独立增删观点 |
| 用户说“本轮暂停表达规范，翻译论文” | 不注入两层表达规则；真实性与项目已有翻译要求保留 |
| 用户隐藏提示 | 不显示表达标记；两层规则仍按任务适用 |
| v1 默认规则从未定制，存在上次内置副本 | 升级为新默认，备份可恢复 |
| 本地规则已增加个人要求或找不到上次内置副本 | 不覆盖，报告保留状态，人工比较后选择性合并 |
| 与 CCL 一起安装 | 保留 CCL hooks、状态与管理段，不调用其执行器 |

## 第三方与个人旧规则

本工具不删除其他工具或个人指令中的写作规则，也不改插件缓存。部署时需检查个人全局指令是否仍含与证据边界冲突的旧段落，并在获准后局部修订其措辞。第三方框架的章节和运行流程保留；真实证据、负结果、比较条件与操作授权不能靠风格偏好撤销。

仓库中的附加规则独立编写，不附带 TJU/Nature 的原文、案例或执行代码；如另行分发第三方内容，应逐文件核对其授权并保留相应署名和许可，不能统一套用本仓库 MIT 标识。
